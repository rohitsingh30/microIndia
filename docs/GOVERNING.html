The product

Owned by the product-engineer agent in docs/product/STORY.md. Every product decision is logged in docs/product/DECISIONS.md.

Track 1 · main

Creator shortlists for brands

A brand writes a need in plain words, for example “Hinglish skincare creators in Pune, 10–50K, honest reviewers, for a sunscreen launch”. It gets a ranked shortlist where every pick points to the 2–3 reels that prove fit.

For: D2C brand marketers and agency planners, equally

Brief→Shortlist + why→Creator dossier→Compare→Save · export · outreach
Track 2 · new

Local finder

Someone in a city finds a local Instagram business for a specific job, for example “eggless photo cake in Vijay Nagar, Indore, under ₹1,500, for Sunday”. Matches show the business's own posts of that kind of work.

For: anyone looking for home bakers, mehendi artists, tailors, tutors, decorators. Starts with 2–3 services in 2–3 cities.

Task + place→Matches + evidence posts→Business card→Contact on their channel

What we promise

Evidence over scores. Every label traces back to real reels. Unknown stays unknown. Nothing is guessed or zero-filled. AI is the interface and the data is the moat. The chat is only as good as the dossiers underneath it, which is why reel analysis comes first.

BUILDING · PHASE 3 · analysis/ + llm.py

The insight engine

Three new task kinds run on the same queue. A new analyzer worker (no browser) runs next to the scraper, so collection never pauses.

media.reel plays, duration, audio, cover, video → mp4→analyze.reel keyframes + first 3 s + Whisper transcript → Claude Sonnet→analyze.creator 15+ reels → Claude Opus dossier

Reel output: hook, format, topic, spoken languages, on-screen text, products and brands shown, sponsored (detected vs disclosed), production quality, tone, audience, brand safety, and why it beat or missed the creator's usual. Every row is versioned with its prompt hash and input hash. Transcripts, frames, audio and raw outputs are kept so analysis can be re-run later. The same engine produces business_cards for the Local finder.

Search / similar / seeds→Queue (tasks)→Scrape profile + 18 posts→Eligibility gate→Creators + features→API→Dashboard / brand search

Feedback loop: every kept creator queues its own “similar accounts” plus every account it mentions. That is why the queue grows faster than it drains.

What scale is realistic

On 5 Oct the system kept about 170 creators per running hour. The README still mentions a target of 1,000,000 profiles. At today's rate that is about 245 days of non-stop running on one laptop and one Instagram account. 10,000 is about 2.5 days, and 50,000 is about 12 days. The target needs to be chosen deliberately (see Decision 3).

Problems found

Ordered by how much they cost us now. Red items lose data or work; amber items slow us down or mislead; grey items are cleanup.

Critical

The watchdog can't see a stalled scraper

The stall check uses the newest finished task of any type. While the sourcer keeps finishing tasks, a dead scraper looks healthy. Its heartbeat also keeps beating while all 8 tabs hang.

watchdog.py:97 · SELECT MAX(finished_at) FROM tasks · 8 leases expired 70 min ago, never reclaimed
Half fixed

Version control is fixed; database backups are not

Fixed 6 Oct: microIndia has its own git repo, with commits as checkpoints. VS Code no longer picks up the empty home-folder repo. Still open: the 224 MB database has one manual backup. A nightly backup worker is in Phase 2.

data/backups has 1 file (5 Oct)
High

Network blips permanently fail work

A short disconnect used up all 3 retries in seconds. 207 profiles, 27 searches and 24 similar lookups are marked failed and won't be retried on their own. Offline errors should wait for the network instead of counting as attempts.

261 tasks · “ERR_INTERNET_DISCONNECTED” · fixable with “Retry all” on Pipeline
High

The target creator keeps changing

The follower band went from 10K–100K to 1K–100K to 500–1M in one day, while the current focus is 500–5K. The constants, insights and sourcing code each define bands their own way. Creators kept under one rule get judged by another.

constants.py · insights.BANDS · sourcing.SIZE_BANDS · skip reason “Business account (old rule)”
High

Discovery is degrading

“Similar accounts” returns “user id not found” for every recent request, and search failed half the time in the last 2 hours. Without discovery the queue still has 27K profiles, but those come from older, broader rules.

sourcer.log · last 2h: search 27 ok / 27 failed · similar 24 / 24 / 32 skipped
Medium

Search and data speak different taxonomies

The scraper labels 36 niches. Brand chat search knows 8, and 284 kept creators have no niche. Niche lists exist in five places.

niches.NICHES · intelligence.TOPIC_TERMS / CATEGORY_STEMS · search_ai.CATEGORIES / CATEGORY_WORDS

A code bug quietly retries profiles

“TypeError: unsupported operand type(s) for -: 'float' and 'str'” appears on several profiles, likely a date stored as text being subtracted from a number.
